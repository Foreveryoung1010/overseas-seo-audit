# 用 GSC 导出做「需求量级」回测

不装任何付费工具，用自己站的真实数据算出每个页面的需求量级，排完序就知道：

- 哪几篇选题对了（量大）
- 哪几篇是自嗨（排名不低但量极小）
- 哪几篇有需求但没排好（**最该优先修的**）

## 用法

1. GSC →「效果」→「网页」→ 右上「导出」→ 下载 CSV
2. 运行：

```bash
node gsc-demand-rank.mjs Pages.csv
```

输出按估算需求量级降序排列，并给出动作建议。

## 原理

```
需求单位 = 曝光 ÷ 展示份额系数
```

系数按平均排名取（**粗估，只用于同站排序，不要当绝对搜索量**）：

| 平均排名 | 系数 | 含义 |
|---|---|---|
| 1–3 | 1.0 | 几乎拿到全部展示 |
| 4–10 | 0.6 | 第一页，展示充分 |
| 11–20 | 0.3 | 第二页 |
| 21–50 | 0.1 | 第三到五页 |
| 50 以上 | 0.03 | 基本不展示 |

## 判读

| 需求 | 排名 | 动作 |
|---|---|---|
| 高 | 差（>20） | **优先修**：扩写、加内链、改标题。这类页面性价比最高 |
| 高 | 好（<20） | 保持，优化标题和描述提点击率 |
| 低 | 好 | 选题错了：停更，别删（等新页面起来再合并） |
| 低 | 差 | 直接放弃，不用管 |

## 注意

- 系数是经验值，**只能横向比较**。不要把它换算成"月搜索量 XX"往外说。
- 「查询数」和「网页」两个标签页的数字有时对不上（统计口径不同），以「网页」为准。
- 曝光为 0 的页面不在这份数据里，不代表没收录。
